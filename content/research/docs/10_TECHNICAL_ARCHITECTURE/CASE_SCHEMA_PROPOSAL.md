# مقترح مخطط القضية (Case Schema) — مسودة 0.1.0

> الملف الآلي: `case_schema.json` (JSON Schema 2020-12). **تم التحقق** من أن المخطط صالح بالأداة `jsonschema` 4.26 (`Draft202012Validator.check_schema`)، وأن قضية مثال خيالية مصغّرة (كأس المعرض المفقود، بلا عنف) تجتازه بلا أخطاء.
> الحالة: مسودة بحثية للمراجعة، لا مخطط إنتاج.
> ملفات قابلة لإعادة التشغيل: `prototypes/case_example_minimal.json` · `prototypes/fairness_check.py` (`python3 fairness_check.py case_example_minimal.json`) · `prototypes/asp/*.lp` (clingo 5.8.2).

## 1. مبادئ التصميم

1. **ثلاث طبقات معرفية منفصلة فعلياً:** الحقيقة (`truth` و`timeline`) ← نطاقات الشخصيات (`character_knowledge`) ← دفتر اللاعب (وقت التشغيل، خارج حزمة المحتوى). `[افتراض تصميمي]` مستمد من نموذج "عالم مرجعي + معتقدات خاصة" في Versu [ATH-SRC-0924].
2. **الدليل كيان يملكه المحرك:** لكل دليل أفعالٌ تمنحه (`acquired_by_action_ids`). لا مسار نصي لإنشاء دليل.
3. **الاستدلال صريح ومراجَع:** كل `inference` له مقدمات، ونتيجة، ونوع علاقة، وقاعدة بالعربية (`rule_ar`)، وربط بمهارة (KO). هذا ما يجعل العدالة قابلة للفحص الآلي [ATH-SRC-0926].
4. **الأكاذيب بيانات لا ارتجال:** `claims` بأنواعها (كذب، خطأ صادق، إشاعة، نصف حقيقة)، ولكل منها دليل يناقضها أو علامة "غير محسوم عمداً".
5. **الزمن رقمي:** دقائق نسبية من لحظة الصفر لتسهيل فحص التعارض الزمني. نص العرض يُشتق من الرقم.
6. **عربي أولاً:** حقول `_ar` إلزامية، و`_en` اختيارية، و`aliases_ar` لصيغ الإملاء المختلفة (الهمزات، و"ال"، والألقاب) التي يحتاجها فاحص الكيانات في العالم المغلق.
7. **المراجعة مرتبطة بالبصمة:** أي تعديل بعد التوقيع يُسقط الموافقة.
8. **متوافق مع وحدات المعرفة:** مراجع `KO-XX-NN-NNN` إلى المكتبات 04 و05 و07 وغيرها.

## 2. خريطة الأقسام

| القسم | الوظيفة | من يكتبه / يراجعه | يُرسل إلى النموذج اللغوي؟ |
|---|---|---|---|
| `meta` | العنوان، والفئة العمرية، والصعوبة، وأعلام المحتوى | المحرر + مراجع العمر | لا |
| `premise` | الخطاف، ودور اللاعب، والحقائق العلنية، و**المعرفة العامة المفترضة** | الكاتب + المراجع الثقافي | جزئياً (العلني فقط) |
| `entities` | الشخصيات (الشخصية والدوافع والأسطر المؤلَّفة)، والأماكن، والأشياء | الكاتب | بطاقة الشخصية فقط |
| `truth` | الحل، والحقائق الذرّية، والادعاءات غير الصحيحة | الكاتب + المراجع العلمي | **أبداً كاملاً** |
| `timeline` | أحداث بزمن ومكان وفاعلين وشهود ودافع | الكاتب | لا |
| `evidence` | سجل الأدلة: المحتوى المرئي، والموثوقية، و**الحدود** | الكاتب + المراجع الجنائي | لا (الواجهة تعرضه) |
| `evidence_graph` | الاستدلالات | الكاتب + مصمم التعلم | لا |
| `character_knowledge` | knows / hides(+reveal_when, cover_claim) / believes | الكاتب | **المسموح فقط وحسب الحالة** |
| `hypotheses` و`misdirection_plan` | الفرضيات المتنافسة والخيوط المضلِّلة ودحضها | الكاتب + المحرر | لا |
| `learning_objectives` | الهدف، والسلوك الملاحظ، ومصادر الدليل التقييمي | مصمم التعلم | لا |
| `mechanics` | الأفعال بشروطها وآثارها ورموز القياس | الكاتب (عبر المحرر) | لا |
| `state_machine` | مخطط حالات بصيغة متوافقة مع XState | يُولَّد غالباً من المحرر | لا |
| `dialogue` | المواضيع وأمثلة الأسئلة وسقف الأدوار | الكاتب | المواضيع المسموحة |
| `rubric` | المعايير، ومن يصحح (حتمي / حَكَم / بشري)، والمستويات، وأمثلة مرجعية | مصمم التعلم | للحَكَم فقط |
| `hint_ladder` | تلميحات متدرجة بمحفّزات وأوزان خصم | الكاتب + مصمم التعلم | لنموذج التلميح فقط |
| `fairness_test` | المتطلبات + نتائج التشغيل الآلي مربوطة بالبصمة | آلي | لا |
| `ending_explanation` | سلسلة الاستدلال، والمسارات البديلة، وما لا يثبته الدليل | الكاتب + المراجع العلمي | لا |
| `expert_review` | توقيعات الأدوار السبعة | المراجعون | لا |

## 3. لغة الشروط (Guard DSL) — بلا برمجة

الشروط بيانات تصريحية يقيّمها المحرك، ويبنيها الكاتب من قوائم منسدلة في المحرر:

```json
{"all": [
  {"has_evidence": "ev_logbook"},
  {"presented": {"evidence_id": "ev_logbook", "to_character": "ch_guard"}},
  {"not": {"in_state": "resolved"}}
]}
```
الأنواع: `has_evidence` و`fact_unlocked` و`presented` و`in_state` و`trust_at_least` و`all` و`any` و`not` و`always`.
لا تعبيرات حرة ولا شيفرة، فيمكن ترجمتها آلياً إلى حرّاس XState [ATH-SRC-0914] وإلى قواعد ASP [ATH-SRC-0926].

## 5. فحص العدالة: نموذج أولي عامل + ترميز ASP

### 5.1 النموذج الأولي (Python، بحث شامل)
كتبنا فاحصاً تجريبياً (نحو 120 سطراً) واختبرناه على قضية المثال. يعمل كما يلي:
1. **سلامة المراجع:** كل معرّف معرَّف، وكل كذبة لها دليل يناقضها.
2. **قابلية الوصول:** نقطة ثابتة على الأفعال والشروط. الشرط `not` يُعامل بتقريب زائد آمن (over-approximation).
3. **الإغلاق الاستدلالي** على مجموعات الأدلة.
4. **التعداد:** كل مجموعات الأدلة **الدنيا** التي تدعم الفرضية الصحيحة وتستبعد الخاطئة، ثم عدد المسارات **المنفصلة**.

نتيجة التشغيل على المثال (مقتطف):
```json
{"integrity_errors": [],
 "fairness": {"unreachable_evidence": [], "solvable": true,
   "minimal_evidence_sets": [["ev_lina_testimony", "ev_logbook", "ev_smell"]],
   "disjoint_paths": 1}}
```
**قراءة النتيجة:** القضية قابلة للحل لكن بمسار واحد فقط. لو رُفع `min_disjoint_proof_paths` إلى 2 (التوصية للإنتاج) لفشل النشر، ولطُلب من الكاتب إضافة دليل بديل، مثل كاميرا الممر أو شاهد ثانٍ. هذا بالضبط نوع الملاحظة التي يحتاجها الكاتب.
**حدود:** البحث الشامل أُسّي، فيصلح حتى نحو 16 دليلاً قابلاً للوصول. وبعدها يلزم ASP.

### 5.2 ترميز ASP مقترح (clingo) — **مُختبَر** على clingo 5.8.2 (Python)
```prolog
% --- facts generated from case JSON ---
evidence(ev_logbook). evidence(ev_smell). evidence(ev_lina).
grants(a_check_log, ev_logbook). grants(a_examine_cabinet, ev_smell). grants(a_interview_lina, ev_lina).
pre_always(a_check_log). pre_always(a_examine_cabinet). pre_always(a_interview_lina).
premise(i_guard_in, ev_logbook). premise(i_guard_in, ev_smell). concl(i_guard_in, h_guard, supports).
premise(i_rami_out, ev_lina).    concl(i_rami_out, h_rami, rules_out).
hyp(h_guard, true). hyp(h_rami, false).

% --- choose a subset of reachable evidence (the player's discovered set) ---
reachable(E) :- grants(A,E), pre_always(A).
{ found(E) : reachable(E) }.

% --- derive inferences ---
derived(I) :- concl(I,_,_), found(P) : premise(I,P).
supported(H) :- derived(I), concl(I,H,supports).
excluded(H)  :- derived(I), concl(I,H,rules_out).

% --- solution condition ---
solved :- supported(H) : hyp(H,true); excluded(H) : hyp(H,false).
:- not solved.

% --- minimality: ask for minimal sets ---
#minimize { 1,E : found(E) }.
#show found/1.
```
**الاستخدام:** `clingo case.lp --opt-mode=optN 0` لتعداد كل المجموعات المثلى. أعاد التشغيل الفعلي المجموعة الدنيا نفسها التي وجدها الفاحص الأولي (`ev_lina` و`ev_logbook` و`ev_smell`)، مع إثبات الأمثلية.

**مسبار العدالة على مجموعة الأدلة الكاملة** (مُختبَر):
```prolog
reachable(E) :- grants(A,E), pre_always(A).
found(E) :- reachable(E).
derived(I) :- concl(I,_,_), found(P) : premise(I,P).
supported(H) :- derived(I), concl(I,H,supports).
excluded(H)  :- derived(I), concl(I,H,rules_out).
unrefuted_false(H) :- hyp(H,false), not excluded(H).   % فرضية خاطئة لا يدحضها أي لعب
true_unsupported(H) :- hyp(H,true), not supported(H).  % الحل الصحيح لا يدعمه شيء
```
نتائج التجربة على ثلاث نسخ:
| النسخة | التعديل | النتيجة |
|---|---|---|
| الأصلية | — | عادلة |
| "خيط مضلِّل" | دليل دافع يدعم فرضية رامي الخاطئة | عادلة، لأن إفادة لينا ما زالت تدحضها. **هذا خيط مضلِّل مشروع.** |
| "مشتبه بلا دحض" | فرضية خاطئة جديدة (h_coach) يدعمها دليل ولا يدحضها شيء | **`unrefuted_false(h_coach)`: غير عادلة، يُمنع النشر** |

وهناك مسبار ثانٍ ("الغموض الجزئي") يبحث عن مجموعة أدلة **جزئية** تدعم فرضية خاطئة دون دحضها. أشار هذا المسبار إلى نسخة "الخيط المضلِّل"، وهذا متوقع: يستطيع اللاعب أن يتوقف مبكراً عند الاستنتاج الخاطئ. فهو لا يصلح مانعاً للنشر، بل يُستخدم لرسم خريطة "نقاط التوقف الخاطئة المحتملة"، التي تُغذّي سلّم التلميحات وأسئلة التأكيد قبل الاتهام النهائي.
**تحذير:** `[تفسير بحثي]` الترميز أعلاه يغطي الشروط من نوع `always` فقط. الشروط المركّبة (`has_evidence` و`presented`) تحتاج قواعد وصول تكرارية لم نكتبها بعد. ترميز ASP جيد يحتاج مختصاً، وأداء المحلّل غير مضمون مع الحجم [ATH-SRC-0926]. clingo له واجهة Python رسمية، وأما نسخة المتصفح فغير رسمية [ATH-SRC-0927]، لذلك يعمل الفحص على الخادم فقط.

## 6. قواعد تحقق إضافية لا يعبّر عنها JSON Schema (تُنفَّذ في الفاحص)

| القاعدة | السبب |
|---|---|
| كل `fact_id` في `knows`/`hides` موجود في `truth.facts` | سلامة المراجع |
| لا تعرف شخصيةٌ حدثاً لم تشهده إلا عبر `told_by` أو `inferred` مع مصدر | منع تسرّب المعرفة [ATH-SRC-0943] |
| `witness_ids` لحدث ما موجودون في المكان نفسه زمنياً | الاتساق الزمني |
| لا شخص في مكانين في فترتين متداخلتين | الاتساق الزمني |
| كل حدث له فاعل وحقل `motivated_by_ar` غير فارغ | القصدية [ATH-SRC-0921] |
| `content_ar` للدليل لا يحتوي نص `rule_ar` لاستدلاله | الدليل يعرض الملاحظة لا الاستنتاج |
| كل `red_herring` له استدلال يدحضه وقابل للوصول | عدالة التضليل |
| كل `learning_objective` مغطّى بمعيار واحد على الأقل في `rubric` | محاذاة التقييم |
| `expert_review` يحوي الأدوار الإلزامية بحالة `approved` وبصمة مطابقة | بوابة النشر |
| عناصر `spoiler_level = 3` لا تظهر في `premise.public_fact_ids` ولا في أي `knows` غير مشروط | حماية الحل |

## 7. قيود المخطط المعروفة
1. **المعتقدات المتداخلة** ("يظن أن فلاناً يعرف") غير مدعومة. هي مكلفة حسابياً [ATH-SRC-0925] ونؤجلها.
2. **عدم اليقين الاحتمالي** في الأدلة مبسَّط إلى ثلاث درجات (`reliability` و`strength`). هذا يحتاج مراجعة من فريق العلوم الجنائية (المكتبة 04) لتجنّب تبسيط مضلِّل.
3. **قيود المخرجات المُهيكلة لدى المزوّدين** لا تدعم المخططات العودية ولا قيود الطول [ATH-SRC-0937]. لذلك هذا المخطط **ليس** مخطط مخرجات النموذج. مخطط الحوار المختصر موجود في `AI_CHARACTER_GUARDRAILS.md`.
4. حقول `trust_at_least` و`time_budget_units` موجودة لكن آلياتها لم تُصمَّم بعد.
5. المخطط لا يحوي حقولاً للوسائط الثقيلة (فيديو). القضايا النصية والصورية أولاً لدعم الاتصال الضعيف.
